## 🧾 What Counts as a Project Here?

A project is not merely a file that exists.

A project is a **portfolio artifact that proves a skill**.

Depending on the topic, a project may include:

- ✅ Source code and scripts
- ✅ SQL queries and schemas
- ✅ Dockerfiles and Compose files
- ✅ Terraform configurations
- ✅ IAM policies and security controls
- ✅ Airflow DAGs and dbt models
- ✅ Detection rules and sample logs
- ✅ Dashboards and notebooks
- ✅ Architecture and data-flow diagrams
- ✅ Screenshots and command outputs
- ✅ Investigation reports and runbooks
- ✅ Tests, validation checks, and monitoring evidence
- ✅ A README explaining the problem, design, result, and lessons learned

The standard is not:

> “I learned S3.”

The standard is:

> “I designed a secure S3 data-lake layout, applied lifecycle and encryption controls, restricted access with IAM, queried the data with Athena, documented the architecture, and explained the trade-offs.”

Build it. Break it safely. Fix it. Test it. Explain it. Commit it 🧱🔥

## 🧪 Recommended Daily Project Structure

```text
day-XX-topic-name/
├── README.md
├── src/                  # Python, Bash, SQL, or application code
├── config/               # YAML, JSON, Terraform, policies, or settings
├── data/                 # Safe sample or generated data
├── tests/                # Validation and test files
├── diagrams/             # Architecture, network, or data-flow diagrams
├── screenshots/          # Evidence of successful work
└── outputs/              # Logs, reports, query results, or dashboards
```

Not every folder needs every subfolder. The structure should serve the project, not become a tiny bureaucracy wearing a lanyard 😭
